GEO 知识库

实施平台深析：geolook / GEORank / GEOFlow / GEOInflow

物种定义见 01 选型地图。本篇只谈实施平台：交付“干完活能验收“，不是只看仪表盘。 全部数据 GitHub API 一手核验于 2026-11-06；机制描述来自各项目 README 原文。

1. aigclink/geolook（808★ / 205 fork / MIT / Python）

定位：单人自托管的端到端 GEO 实施平台，“状态→诊断→策略→工单→执行→验证“六段闭环。README 自我定位明确对标监测 SaaS：差异在闭环深度走到“工单+资产+程序化验收+客户交付包”。

优势（README 可证实）：

  • 验收是可计算的：工单带验收标准，示例项目 86%（18/21）可程序化验证；回归自动重开工单。这是和“人工勾清单“型工具的本质区别。
  • 诊断判据硬：四层依赖链（Access→Orientation→Understanding→Quotability）自动算修复顺序；robots 解析按 RFC 9309 合规实现（抓通配符组、共享 UA 组、特异性覆盖）；WAF/CDN 用真实 AI 爬虫 UA 差分探测——抓“robots 放行但 CDN 403“这类浏览器视角盲区。
  • 中文引擎一等公民：GLM/豆包/DeepSeek/Kimi/MiniMax/百度 AI 进采样矩阵；评分锚定 602 prompts/21,143 citations/187,818 条中文去重引用的公开语料（即 GEOLab 数据集，见 05 研究框架）。
  • 零门槛部署：Python 3.9+，仅 requests/bs4/lxml 三个依赖；零 API key 走手动采样表；文件即数据库（work/ 下 JSON/Markdown），git init 即备份。
  • 诚实文化：未测就显示“unmeasured“不造假；没有官方 API 的平台（微博/小红书/头条/B站）明确不集成并说明原因，只给 webhook 桥；发布逐篇人工确认。

不足：

  • 停更：push 停在 2026-08-10（近 3 个月），2 个贡献者（主作者 46 commits）——爆星后个人项目停滞的典型样本。选用 = 接受自维护 fork。
  • 单机单用户：无账号体系无团队协作（README 自认，称“刻意设计“）。
  • 采样量和频率受自己的 API 预算约束；“疑似负面“标记只是人审线索不是结论。

应用场景：独立顾问/小团队接 GEO 单子的最贴手持具——诊断报告、策略、执行计划、工单 CSV、验收单都是对客交付物形态。与本库关系：advanced/08（工单+风险分级）、advanced/11（四层模型）、guide/10（中文引用榜）的方法层与它同源；它的“客户交付包“就是 B2B GEO 服务的交付物模板。

2. yaojingang/GEORank（533★ / 122 fork / Apache-2.0 / Next.js+FastAPI）

定位：面向团队的自托管 GEO 工作台，官方演示站 georankhub.com。七段流程：发现→诊断→问答→规划→拓展→结构化→管理。

优势：

  • 重基建：PG/Redis/Qdrant/Neo4j 全家桶，支持多人协作、API 池（Provider 测试/轮询/故障转移）、私有化部署——这是为“卖给客户做二次开发“设计的架构。
  • 工具直接可用：JSON-LD 生成器、llms.txt 生成器、AI 友好度评分、GEO 标题生成器、知识库生成器，拿来即用。
  • 内容代码分离：公开仓库只放代码+模板+demo，私有内容不随仓库发布——开源运营的干净做法。
  • 活跃：push 10-28。

不足：

  • 部署门槛高：五套存储中间件，个人用户跑不起来（与 geolook 的“三依赖“形成两极）。
  • 诊断深度未经第二方验证：README 未披露判据来源与语料，规则引擎质量存疑（对比 geolook 至少公开了 references/ 方法层）。
  • 收录的“专家频道“是内置 5 人静态资料，社区属性弱。

应用场景：营销公司/咨询公司要私有化部署一套给客户用的 GEO 门户，或要在开源代码上二次开发自己产品的团队。与本库关系：它的 30/60/90 天方案模块可对照 case-studies/04 的 90 天推演。

3. yaojingang/GEOFlow（4032★ / 911 fork / ⚠️AGPL-3.0 / PHP Laravel）

定位：企业官网的 GEO 内容生产与分发运营系统：可信知识→AI 生产→AI 质检门禁→人工审核→多站点分发→数据分析，一条链路全留痕。

优势：

  • 质检门禁是稀缺件：AI 生成和人工放行之间有机器关卡，保留质检证据链——企业内容治理的刚需形态，同类开源少见。
  • 工程成熟度：有 CI、版本化发布（3.1.0 稳定版/3.2.0-beta 预览）、蓝绿部署与自动迁移文档；Chrome 协作发布；活跃（push 11-04）。
  • fork 数（911）与 star 比例健康，绝对量大。

不足：

  • AGPL-3.0 是硬雷：把它嵌入你的 SaaS 对外提供服务，触发传染条款，源码必须开源。商用集成前必须过法务，本书引用其架构思想不受影响（思想不受版权保护）。
  • PHP/Laravel 栈对 Python/Node 团队是维护孤岛。
  • star 曲线仍需观察：2026-04 创建冲上 4k，同作者矩阵效应明显（见存疑区方法论），功能口碑样本不足。

应用场景：有 PHP 运维能力的企业自建内容中台做 GEO 运营；不适合个人。与本库关系：advanced/01（内容优化判据）可作为其质检门禁的规则参考源。

4. yaojingang/GEOInflow（810★ / 253 fork / MIT / TypeScript）

定位：自托管 Web+AI 爬虫分析：访客、AI 搜索引荐、抓取日志三合一。严格说卡在监测与实施之间，因带部署侧配归因被归入本篇。

优势：爬虫日志维度是差异化——能回答“GPTBot 到底来没来、来了抓了什么“，这是访问层诊断的一手证据（呼应 advanced/09、10）。MIT 可放心用。活跃（push 11-03）。

不足：创建 2026-10-26，11 天 810★/253 fork，增速远超自然扩散曲线，已列存疑区——star 热度不采信，功能按 README 评估。产品成熟期数据（issue 处理能力、日志解析准确度）无公开样本。

应用场景：想在自己服务器上落 AI 爬虫日志并配 GA4 引荐拆分的站长。与本库关系：advanced/10（GA4 AI 引荐配置）的落地载体候选。
