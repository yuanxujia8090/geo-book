# GEO 逆向（一）：黑盒里探规则

> 引擎不公开规则，但它的行为泄漏了规则。这一篇讲怎么从"问它问题"反推它的选择逻辑。

## 什么是 GEO 逆向

正面 GEO 是"我改内容 → 祈祷引擎引用"。逆向 GEO 反过来：**把引擎当黑盒，控制输入、观察输出，反推它的筛选规则，再按规则施工。**

你没法读它的代码，但它每次回答都在"泄题"——引用了谁、放在第几位、抄了哪一段，这些都是可观测数据。攒够数据，规则就浮出来了。

## 引擎的四段管线（逆向的地图）

每条引用都经过四站（gugubrand 梳理），每站都有可探测的行为特征：

```
爬取 crawl → 切块 chunk → 检索 retrieve → 选择 select
```

| 站点 | 泄漏的信号 | 你怎么探 |
|------|-----------|---------|
| 爬取 | 来不来、多久来一次 | 服务器日志数 AI UA（advanced/09） |
| 切块 | 它抄的片段边界在哪 | 收集引用原文，对照你页面找切块习惯 |
| 检索 | 什么问题召回什么域名 | 冻结问题集 × 多采样统计（advanced/12） |
| 选择 | 同批候选里选谁、放第几 | 同题多引擎对比、引用位次记录 |

一个已知的结构性事实：**同时被 ChatGPT 和 Perplexity 引用的网站只有约 11%**（gugubrand 口径，medium 置信）——两家检索索引基本是两个世界，逆向必须分引擎做，"AI 的算法"不存在。

## 五种探测手法（白帽，可直接用）

### 1. 新鲜度探针：判断它此刻连没联网
问一个只有今天发生的事件。答得出 = 走了实时检索；答得旧 = 靠参数记忆。同一问题在网页版和 API 各问一次，经常结果不同（API≠Web 的实测版，见 advanced/12）。

### 2. 引单采集：把"引用域名清单"当数据攒
每次采样记下答案里全部引用域名（不只记有没有你）。攒 100 次采样后统计：这个引擎爱引哪类站、你所在的品类被谁垄断。**CN-GEO 数据集（guide/10 的官网 1.37%）本质上就是这种逆向的大规模成品**——你用小得多的规模做同样的事。

### 3. 金丝雀页：验证检索通道通不通
造一个只有你知道的新页面，塞一句全网独一无二的句子（金丝雀句），发布后定期拿这句话提问。哪天 AI 原样说出这句 → 确认"爬取→索引→检索→生成"全链路已通，且能定位是哪条通道带来的。这是最干净的管线验证法。

### 4. 单变量改写：一次只改一件事，测引用变化
挑一个稳定不被引的页面，只加"数字块"，发布，等 1-2 周，同问题重采样；下一轮只改标题句式。**一次一个变量**，引用率的前后差值（citation delta）才能归到这一项上。一次改五样，等于没测。这本质是 Princeton GEO 论文黑盒优化框架的手工版——AutoGEO（ICLR'26）做的事就是把这个循环自动化。

### 5. 幽灵引用鉴别：它引用的到底存不存在
AI 会编造看似合理的引用（ghost citations，GhostCite 论文 arXiv:2602.06718 已大规模量化）。逆向时反过来用：**点开它给的每个引用链接**——链接失效/内容对不上 = 这条是参数记忆脑补的，不是检索来的。你的内容被"幽灵化"（AI 说了你的话但不给链接）说明它从二手转载学到的你，这正是要去第三方阵地铺原文的理由。

## 逆向的边界（必须先说）

- **理解规则 ≠ 操纵规则。** GEO-Bench（arXiv:2605.29107）实测过黑帽操纵策略：短期有效、且专门给"隐蔽性"打分——意味着引擎方也在建反制。逆向的产出应该是"按它喜欢的结构写真实内容"，不是"骗过它塞假内容"。
- 引擎行为随版本漂移（模型更新、索引重建），逆向结论有保质期——每季度重探，别把去年的规则当定律。
- 单引擎结论不外推：11% 重合率说明一切。
